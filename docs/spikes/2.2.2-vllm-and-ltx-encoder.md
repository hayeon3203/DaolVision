# Spike 2.2.2 — LLM/VLM vLLM 및 LTX 텍스트 인코더 교체 검토

작성: 2026-07-30 · 관련: PRD S1 · 상태: 완료

## 결론

- `NVIDIA-Nemotron-3-Nano-4B-BF16`: vLLM 0.26.0 서버 기동 성공, 그러나 현재
  S1 씬 분할 품질과 structured output은 기존 Ollama Q4 경로보다 나빠 **전환 보류**.
- `Nemotron-Labs-Diffusion-VLM-8B`: vLLM 기동 실패. 해당 아키텍처가 vLLM에
  없고 Transformers 버전도 충돌하므로 **전용 Transformers 4.57.1 서버만 가능**.
- LTX의 `Gemma 3 12B FP8`를 Diffusion VLM-8B로 교체: **drop-in 불가능**.
  새 projection 및 identity conditioning/LoRA 재학습이 필요한 연구 과제다.

## vLLM 실측

환경:

```text
vLLM 0.26.0
torch 2.11.0+cu130
transformers 5.12.1
NVIDIA GB10
```

### Diffusion VLM-8B

기동 명령:

```bash
vllm serve nvidia/Nemotron-Labs-Diffusion-VLM-8B \
  --host 127.0.0.1 --port 18000 --trust-remote-code \
  --gpu-memory-utilization 0.25 --max-model-len 4096
```

서버 초기화 전에 실패:

1. 원격 모델 코드가 Transformers 5.12에서 제거된
   `sdpa_mask_older_torch`를 import.
2. vLLM이 `NemotronLabsDiffusionVLMModel`을 지원하지 않는다고 명시적으로 거부.

따라서 모델 카드의 일반적인 vLLM 예시는 현재 vLLM 0.26.0/이 체크포인트 조합에서
재현되지 않는다.

### Nemotron 3 Nano 4B BF16

`NemotronHForCausalLM`으로 정상 인식. 체크포인트 7.40GiB, weight memory
7.47GiB. 최초 다운로드+로드+compile/warmup 후 OpenAI 호환 API가 기동됐다.

```bash
vllm serve nvidia/NVIDIA-Nemotron-3-Nano-4B-BF16 \
  --host 127.0.0.1 --port 18001 --trust-remote-code \
  --gpu-memory-utilization 0.15 --max-model-len 4096
```

S1 테스트:

- thinking 기본값: reasoning이 512토큰을 소비해 JSON 도중 잘림, 36.92초.
- `enable_thinking=false`: 4개 씬 지시에도 2개만 반환, 4.04초.
- JSON Schema `minItems=maxItems=4`: `[` 뒤 공백만 생성하다 400토큰 종료,
  15.75초.

기존 Ollama Q4 벤치는 JSON 파싱 3/3이므로 vLLM BF16으로 바꿀 근거가 없다.

## Gemma 3 12B 교체가 어려운 이유

LTX의 Gemma는 단순 prompt enhancer가 아니라 diffusion transformer에 전달할
conditioning tensor를 만드는 **학습된 텍스트/비전 인코더**다.

현재 ComfyUI 구현:

- Gemma 3 12B: 48 layers, hidden size 3840, vocabulary 262208.
- 각 토큰의 전체 layer 표현을 사용해 `3840 * 49` 입력의 LTX 전용 projection을
  통과시킨다.
- projection은 video/audio conditioning 공간으로 매핑한다.
- BFS의 Gemma-Vision identity 경로도 LTX 자체 Gemma embedding 공간을 전제로 한다.

Diffusion VLM:

- 34 layers, hidden size 4096, vocabulary 131073.
- Pixtral 계열 vision tower와 별도 tokenizer/chat template.
- LTX projection이 기대하는 입력 shape와 embedding 의미 공간이 모두 다르다.

따라서 파일 이름이나 loader만 바꾸면 shape mismatch가 발생한다. 억지로 차원을
맞추는 선형 adapter만 추가해도 의미 공간이 맞지 않는다. 실제 대체에는 최소한:

1. Nemotron의 여러 hidden state를 LTX가 기대하는 conditioning으로 바꾸는 새
   projection 학습,
2. LTX transformer의 cross-attention 적응 학습,
3. Best Face-ID LoRA와 BFS identity 경로 재학습/품질 검증

이 필요하다. 7일 데모 범위가 아니라 모델 연구/훈련 범위다.

Nemotron을 **prompt enhancer**로 사용해 더 좋은 텍스트를 만든 뒤 기존 Gemma
encoder에 넣는 것은 가능하지만, 이 경우 Gemma 메모리는 제거되지 않는다.
