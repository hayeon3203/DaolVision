# Spike 2.2.3 — Nemotron Nano 12B v2 VL 양자화 메모리 검토

작성: 2026-07-30 · 관련: PRD S1 · 상태: 산정 완료, 양자 모델 실측 전

## 결론

`nvidia/NVIDIA-Nemotron-Nano-12B-v2-VL-BF16`은 vLLM 0.26.0에서
`NemotronH_Nano_VL_V2`로 정상 인식되고 24.57GiB weight load까지 성공했다.
사용자 요청에 따라 inference/profile 전에 중단했다.

LLM/VLM 피크 목표가 8~10GB라면:

- BF16: 제외.
- FP8: 제외.
- NVFP4-QAD: 가장 가까우나 checkpoint만 9.89GiB라 런타임 피크는 목표 초과 예상.

따라서 12B VL은 **기능적으로 적합하지만 메모리 목표에는 부적합**하다.

## 공식 체크포인트 크기와 예상 피크

| 모델 | HF 저장 크기 | GiB | 예상 런타임 피크 | 판정 |
|---|---:|---:|---:|---|
| BF16 | 26.4GB / 실측 weight 24.57GiB | 24.57 | 28~34GiB | 제외 |
| FP8 | 15,415,445,512 bytes | 14.35 | 16~20GiB | 제외 |
| NVFP4-QAD | 10,618,065,728 bytes | 9.89 | 12~14GiB | 목표 초과 예상 |

예상 피크는 weight 외 RADIO vision activation, Mamba/KV cache, CUDA context,
vLLM graph/workspace를 포함한 범위다. 실제 값은 `--enforce-eager`,
`--kv-cache-memory`, 이미지 tile 수, context 길이에 따라 달라진다. 그러나
NVFP4도 weight만으로 10GiB에 근접하므로 **전체 peak 10GB 이하는 구조적으로
보장할 수 없다.**

## 현재 텍스트/LTX 메모리 비교

| 구성 | weights 기준 | 용도 |
|---|---:|---|
| Nemotron 3 Nano 4B Ollama Q4 | 2.84GB 파일, 런타임 약 4~6GB 예상 | S1 씬 분할 |
| LTX Gemma 3 12B FP8 | 12.30GiB | LTX conditioning |
| LTX text projection BF16 | 2.15GiB | Gemma→LTX conditioning |
| Gemma+projection 합계 | 14.45GiB + activation | I2V 단계에서만 필요 |

Gemma는 일반 대화 LLM이 아니라 LTX 모델과 Face-ID 경로가 학습된 conditioning
encoder라 제거할 수 없다. Nemotron VLM과 Gemma를 동시에 상주시킬 이유도 없다.

권장 phase:

1. 씬 분할/캡션 phase: 작은 LLM/VLM만 load.
2. 완료 후 완전히 unload.
3. I2V phase: LTX + Gemma + projection + Face-ID만 batch load.

NVFP4 VLM과 LTX Gemma를 같이 상주시키면 두 인코더만 대략 27~32GiB 런타임
메모리를 요구하며, 여기에 LTX 22B/LoRA/VAE가 더해진다.

## 채택 판단

- 엄격한 8~10GB: 기존 Nemotron 4B Q4 유지 + 더 작은 캡션 VLM을 별도 선정.
- 12~14GB 허용: `NVIDIA-Nemotron-Nano-12B-v2-VL-NVFP4-QAD`를 다음 스파이크
  대상으로 삼을 수 있음.
- FP8은 공식 벤치상 BF16 품질과 거의 같지만 메모리 목표에는 의미가 없음.

NVFP4 실측을 한다면 다음 제한으로 시작한다.

```bash
vllm serve nvidia/NVIDIA-Nemotron-Nano-12B-v2-VL-NVFP4-QAD \
  --quantization modelopt_fp4 \
  --max-model-len 4096 \
  --limit-mm-per-prompt.image 1 \
  --enforce-eager
```
