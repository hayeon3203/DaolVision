# Spike 2.2.1 — Nemotron Labs Diffusion VLM 단일 모델 교체

작성: 2026-07-30 · 관련: PRD S1, Plans.md 2.2.1 · 상태: 완료(부분 통과)

## 질문과 결론

실제 운영 코드 `video_generator/langgraph/tools.py`와 `run_agent.sh`의
`qwen3.5:9b`를 `nvidia/Nemotron-Labs-Diffusion-VLM-8B` 하나로 바꿔 S1의
텍스트 처리와 이미지 캡션을 모두 맡길 수 있는지 GB10에서 검증했다.

**결론: 캡션 용도는 통과, 텍스트 씬 분할 용도는 실패. 현재는 단일 모델로
프로덕션 교체하면 안 된다.**

- 캡션: 정확한 영어 주 피사체 캡션, 2.44초 — 통과.
- 텍스트: 추론 자체는 6.92초로 성공했지만 4개 씬 모두 원문 전체를 반복하고 JSON
  배열의 여는 `[`를 누락 — S1 씬 분할 품질/파싱 게이트 실패.
- 권장 배선: 텍스트는 이미 벤치를 통과한
  `NVIDIA-Nemotron-3-Nano-4B-GGUF`, 캡션만 Diffusion VLM-8B. 이 구성은
  Qwen을 완전히 제거하지만 모델 하나로 통합하지는 않는다.
- 단일 모델 재검토 조건: structured-output 강제 또는 AR 디코딩 경로가 제공되고,
  실제 `node_split_scenes` 프롬프트 3회가 모두 JSON 파싱과 장면별 의미 분리를
  통과할 것.

## 환경과 호환성

| 항목 | 결과 |
|---|---|
| 장비 | NVIDIA GB10 |
| Torch | 2.12.1+cu130 |
| 체크포인트 | BF16 17.9GB, 4 shards |
| 모델 로드 | 88.53초 |
| peak CUDA allocated/reserved | 16.91 / 17.23GiB |
| 라이센스 | NVIDIA Source Code License v1 |
| 런타임 | Transformers 네이티브, Ollama 아님 |

모델 카드에는 `transformers>=5.0.0`이라고 되어 있으나 실제 원격 코드는
`sdpa_mask_older_torch`를 import한다. 현재 영상 환경의 Transformers 5.12.1과
격리 환경의 5.0.0 모두 import에 실패했다. 체크포인트가 기록한 **4.57.1**에서만
정상 로드됐다. 따라서 기존 `huyuan-env`를 변경하지 말고 전용 프로세스/venv를
사용해야 한다.

```bash
python -m venv --system-site-packages .venv-nemotron
.venv-nemotron/bin/pip install -r docs/spikes/nemotron-diffusion-vlm-requirements.txt
.venv-nemotron/bin/python docs/spikes/probe_diffusion_vlm.py
```

## 실측 출력

텍스트 입력은 PRD S1의 발사 → 우주유영 → 외계행성 → 귀환 한국어 스토리이며,
정확히 4개 JSON 객체를 요구했다.

```text
scene_split: 6.92s, NFE 65
출력: {"id":1,"text":"...(전체 원문)...",...}, ... {"id":4,...}]
판정: 여는 [ 누락, 장면별 분리 실패, parse_json_lenient 실패
```

캡션 입력은 `video_generator/assets/howtouse1.png`의 정장 차림 동아시아 여성
인물이었다.

```text
caption: "Capable East Asian corporate employee."
latency: 2.44s, NFE 24
판정: 주 피사체/인구통계/복장 의미가 맞아 caption_image 용도 통과
```

## 실제 코드에 미치는 영향

현재 코드는 Ollama 전용이다.

- `call_llm`: `POST :11434/api/chat`
- `caption_image`: `POST :11434/api/generate`, base64 `images`
- `run_agent.sh`: 텍스트/비전 모델 이름만 환경변수로 설정

Diffusion VLM은 모델명만 바꿔 이 API를 사용할 수 없다. 채택 시 별도 상주 서버가
OpenAI 호환 `/v1/chat/completions`를 제공하게 하고, `tools.py`에 Ollama와 분리된
VLM URL/호출 어댑터를 추가해야 한다. 17.23GiB 상주 비용은 기존 Day1 OOM 결과상
배치 온디맨드 오케스트레이션에 포함해야 한다.
