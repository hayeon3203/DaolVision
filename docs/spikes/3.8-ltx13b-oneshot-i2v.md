# Spike 3.8 — LTX-Video-0.9.8-13B-distilled 단발샷 I2V (비Face-ID)

작성: 2026-07-31 · 관련 Task: Plans.md 3.8 · 상태: cc:완료(핵심 검증 통과, 후속 버그 1건 남음)

## 목표

3.4/3.5에서 LTX-2.3-22B Face-ID 파이프라인(5초/523초, step·양자화·attention
레버 전부 순이익 없음)에 대한 대안으로, "이미지 1장 + 텍스트 → 짧은 영상"
단발샷 전용의 더 가벼운 비중국 I2V 모델을 찾는다(`model-selection-i2v.md`가
이미 "1순위 속도 스파이크"로 지목한 LTX-Video distilled 계열). Face-ID
LoRA 없이도 원본 사진이 첫 프레임으로 직접 조건부 입력되므로, 단일 짧은
클립 내에서는 identity가 자연히 유지될 것이라는 가설을 검증.

NVIDIA Cosmos-Predict2-2B-Video2World도 같이 검토했으나 공식 모델 카드에
identity 보존 관련 언급이 전혀 없고 "입력 영상을 정확히 따라가지 못할 수
있음"이 명시돼 있어 제외(별도로 NVIDIA Cosmos3-Super-Image2Video도 확인 —
64B, 8×H200급 멀티GPU 전제라 GB10 1노드로는 시도 자체가 불가). Cosmos는
identity 없는 순수 T2V 용도로 재검토 대상(7.3 참고).

## 채택 모델

`Lightricks/LTX-Video`(🇮🇱, LTX-2.3와 동일 계열) 리포의
`ltxv-13b-0.9.8-distilled-fp8.safetensors`(15.7GB, fp8). ComfyUI 코어에
LTX 지원이 내장돼 있어(`comfy_extras/nodes_lt.py`) 별도 커스텀 확장 설치
불필요.

## 막힌 지점 4개와 해결

1. **safetensors 파일 손상** — 최초 다운로드가 `curl ... | tail -20`으로
   파이프에 물려 curl 자체의 실패가 파이프의 exit code에 가려짐(마지막
   커맨드인 tail의 exit code만 반영됨). `SafetensorError: incomplete
   metadata, file not fully covered`로 뒤늦게 발각. `curl -fL --retry 3`로
   파이프 없이 재다운로드해 해결(100% 완주 로그로 직접 확인).
2. **`LTXBaseModel.forward()` 가 `attention_mask`를 기본값 없는 필수
   인자로 요구** — `comfy/model_base.py`의 `LTXV.extra_conds()`가
   `attention_mask`가 `None`일 때 아예 딕셔너리 키 자체를 채우지 않음(LTX-2.3/
   AV 경로는 항상 별도 인코더 체인으로 뭔가 채워주지만, 클래식 0.9.x 단순
   그래프는 그 인코더를 안 씀 — 이 ComfyUI 버전이 2.3/AV 위주로 리팩터되며
   생긴 회귀로 추정). **`comfy/model_base.py` 1줄 패치**: `None`일 때도
   `comfy.conds.CONDConstant(None)`으로 명시적으로 채움(`CONDRegular`는
   배치사이즈 repeat 연산이 있어 `None`에 못 씀, `CONDConstant`는 값을
   그대로 통과시켜 안전). 기존 LTX-2.3 파이프라인(항상 mask 있음)의 동작은
   그대로 유지, `None` 케이스만 추가로 안전해짐.
3. **`LTXAVTextEncoderLoader` 오적용** — 이름 그대로 AV(2.3) 전용 인코더
   로더라 이 13B 구버전 체크포인트와 `ckpt_name` 매칭 자체가 안 맞음
   (`ValueError: invalid tokenizer`). 일반 `CLIPLoader(type="ltxv")`로
   원복.
4. **텍스트인코더 아키텍처 불일치** — 로컬에 있던
   `umt5-xxl-enc-bf16.safetensors`는 실제로 UMT5-XXL(4096차원)이 맞지만
   키 이름 패턴(`blocks.N.attn.q/k/v/o` 식)이 **Wan 파이프라인 전용 변환
   포맷**이라 ComfyUI 코어 LTXV 로더가 인식 못 하고 SD1.5 시절 CLIP-L
   (77×768) 취급으로 fallback해 `RuntimeError: mat1 and mat2 shapes
   cannot be multiplied (77x768 and 4096x4096)`. LTX-Video 0.9.x는 실제로
   **표준 T5-XXL**(UMT5 아님)을 씀 —
   `comfyanonymous/flux_text_encoders`의 `t5xxl_fp8_e4m3fn_scaled.safetensors`
   (4.9GB, ComfyUI 유지자가 직접 배포하는 표준 포맷)로 교체해 해결.

## 결과

- **8-step 샘플링 20초(2.67초/step), 전체 30.22초** — LTX-2.3 Face-ID
  baseline(523초) 대비 17배, `model-selection-i2v.md`가 정한 채택 게이트
  (warm 생성 120초 이내)를 여유 있게 통과.
  텍스트인코더는 `MochiTEModel_` 클래스로 로드됨(ComfyUI가 T5-XXL 계열을
  내부적으로 이 래퍼로 처리 — Mochi와 아키텍처 공유, 정상).
- 참조 이미지(`geonho_ref.jpg`, 3.4에서 사용자 승인받은 동일 스톡 이미지)로
  "waving hello and smiling" 프롬프트 실행, 97프레임 애니메이션 WEBP
  산출. 눈판정: 헤어·목걸이·턱선 디테일이 프레임 전체에서 일관되게 유지,
  twin/ghosting 등 구조적 파탄 없음, 프롬프트대로 자연스러운 웃음/손짓
  모션.

## 알려진 후속 버그(다음 실행에서 수정 필요)

**해상도 하드코딩이 원본 사진 비율과 안 맞음** — 테스트 스크립트가
`LTXVImgToVideo`에 768×512(가로, 비율 1.5)를 고정값으로 넣었는데 원본
`geonho_ref.jpg`는 856×1141(세로, 비율 0.75)라 얼굴 상단(이마)이 크롭됨.
모델 품질 문제 아님 — 다음 실행은 세로 비율에 맞는 512×704(비율 0.73, LTX
32배수 제약 준수)로 교체해 재검증 필요.

## 결론

- **채택**: LTX-Video-0.9.8-13B-distilled를 "I2V 단발샷(비Face-ID)" 용도로
  채택. 캐릭터 다중 씬 일관성이 필요한 S1 스토리 파이프라인용 LTX-2.3
  Face-ID와는 별개 트랙 — 서로 대체 관계 아님, 신규 UI 카테고리("I2V")
  전용.
- **미해결**: 해상도 종횡비 버그(위), 정면 외 측면·가림 구도 추가 검증
  아직 안 함(`model-selection-i2v.md` 채택 게이트의 "정면·측면·가림 장면
  얼굴 일관성" 항목 미완료).
- **후속**: `docs/model-selection-i2v.md`·`docs/PRD.md`(UI 카테고리·모델
  스택 표) 갱신, `:8700 /i2v` 엔드포인트 신규 구현 필요(현재는 ComfyUI
  직접 호출 테스트 스크립트만 존재, 게이트웨이 배선 안 됨).
