# 가상 기업 로고 + 하드웨어 장비 영상 일관성 스파이크

작성일: 2026-08-12 · 대상: `langgraph/`(agent 게이트웨이, `:8700`)

## 목표

`agent` 카테고리에서 가상 기업(DaolFusion) 로고가 붙은 하드웨어 장비 이미지를
생성 후, 그 로고가 멀티씬 영상에서 일관되게·자연스럽게 유지되는지 검토한다.
현재 사용 중인 모델(FLUX-schnell, LTX-Video i2v_14b subject_ref 경로)로 가능한지,
그리고 **스크립트/API 직호출 테스트 결과가 실제 LocalAI UI에서도 동일하게
재현되는지**까지 확인한다 — 과거 "테스트로는 확인했는데 프론트에서 보니
불만족스러웠다"는 반복 재발 문제를 이번엔 검증 절차 자체에 반영한다.

시간 제약 없음. 결과물은 실측 스파이크 기록 + 이 설계 문서.

시나리오는 순수 로고 일관성 검증에 그치지 않고 "장비가 조용히 일하는 동안
삶은 풍족해진다"는 메시지를 담은 하루 몽타주로 구성 — 사람이 등장하는 씬에서도
장비의 로고가 흔들림 없이 유지되는지까지 함께 본다(사람+로고 동시 등장이
로고만 있는 씬보다 더 현실적인 스트레스 테스트).

## 배경 — 이미 존재하는 재사용 지점

이 기능은 신규 개발이 아니라 기존 nonhuman 참조(subject_ref) 경로를 로고+장비
케이스에 실측 적용하는 것이다.

- `nodes.py` `_NONHUMAN_TEXT`/`_NONHUMAN_HINTS` — 씬 텍스트/캡션에 "로고",
  "제품", "장비(device)" 등이 있으면 `subject_type="nonhuman"`으로 결정론 판정.
- `_normalise_image_role` — `subject_type="nonhuman"`이면 무조건
  `image_role="character_ref"`.
- `tools.generate_subject_ref_clip` → `_generate_reference_clip(subject_ref=True)`
  — 참조 이미지 전체를 첫 프레임 latent로 고정(`i2v_14b` 워크플로,
  `LTX_FACEID_WIDTH/HEIGHT` = 1280×704). 얼굴 Face-ID LoRA 경로(FACE_WORKFLOW)와는
  완전히 별개 그래프 — 6.12(해상도 크롭이 얼굴 identity 붕괴시킨 버그)가 이 경로에도
  똑같이 적용되는지는 미확인, 이번 스파이크에서 확인 대상.
- 참조 이미지가 1장이면(Task 6.17) LLM의 씬별 매칭 판단을 무시하고 전 씬에
  강제 매칭 + 캡션 기반 human/nonhuman 1회 판정 — 이번 케이스(로고+장비 사진 1장)에
  정확히 해당, 씬마다 매칭이 흔들리는 비결정성 리스크는 이 부분에서는 낮음.

## 테스트 자산

- **메인 로고**: 사용자 제공 DaolFusion 로고(파란 원, 나무·회로 실루엣,
  `DaolFusion_세로_tree.png`) — 직접 준비한 파일 사용, T2I로 새로 생성하지 않는다
  (텍스트/로고 렌더링 품질이 T2I 모델 한계에 좌우되는 변수를 제거).
- **파트너 배지**: NVIDIA 로고(`NVIDIA.png`)를 "Powered by NVIDIA" 배지로
  DaolFusion 로고 옆(하단, 작게)에 배치 — 실제 GB10이 NVIDIA 하드웨어인 만큼
  파트너 배지 관행(예: "Intel Inside")과 동일한 구도. 두 로고 크기가 다르므로
  (DaolFusion 크게/주 브랜딩, NVIDIA 작게/배지) 작은 배지가 씬마다 뭉개지지
  않는지가 별도 검증 포인트 — 아래 리스크 5 참고.
- **장비**: GB10 워크스테이션(NVIDIA GB10 기반, DaolVision이 실제 구동 중인
  장비와 개념 동일 — 가상이 아니라 실물 폼팩터를 재사용해 프롬프트/합성
  난이도를 낮춘다).
- **로고→장비 합성 경로**: DaolFusion 로고 파일 + NVIDIA 로고 파일 + GB10
  워크스테이션 사진을 Flux Kontext I2I로 합성해 "듀얼 로고가 새겨진
  워크스테이션" 참조 이미지 1장 생성. (T2I 단독 생성 대신 I2I 합성을 택함 —
  로고 정확도를 프롬프트가 아니라 입력 이미지로 통제하기 위함.)
- **스타일**: cinematic 1개.

## 시나리오 — 하루 몽타주 ("장비가 조용히 일하는 동안 삶은 풍족해진다")

`node_split_scenes`가 시나리오를 정확히 4개 씬으로 강제 분할하므로(코드 제약,
`nodes.py` system prompt), 앞서 "2~3씬"으로 잡았던 범위를 4씬으로 조정한다.
사람이 등장하는 씬에서도 참조 이미지(듀얼 로고 워크스테이션)는 Task 6.17
단일참조 강제 매칭으로 전 씬에 character_ref로 붙는다 — 인물 자체의 identity
일관성은 이번 스파이크 범위 밖(별도 참조 이미지 없이 매 씬 새로 생성), 검증
대상은 어디까지나 장비의 로고 일관성이다.

시나리오 원문(script_text, 그대로 agent에 입력):

> 아침, 사람이 출근 준비를 하는 동안 책상 위 DaolFusion GB10 워크스테이션이
> 이미 조용히 켜져 데이터를 정리하고 있다. 낮, 사무실에서 사람은 회의와 창작에
> 몰입하고 워크스테이션은 화면에 진행률을 띄운 채 반복 작업을 대신 처리한다.
> 저녁, 사람이 가족과 식탁에 둘러앉아 웃는 동안 워크스테이션은 거실 한쪽에서
> 여전히 조용히 켜져 있다. 밤, 다들 잠든 집 안에서 워크스테이션의 로고만 은은히
> 빛나며 여전히 작동하고 있다.

| 씬 | 내용 | 카메라 | 참고 mood(제안) | 로고 프레이밍 |
|---|---|---|---|---|
| 1 | 아침, 출근 준비 + 책상 위 워크스테이션 | 미디엄샷 | calm | 클로즈업(핵심 검증) |
| 2 | 낮, 사무실 몰입 + 배경의 워크스테이션 | 와이드~미디엄 | neutral | 배경 요소 |
| 3 | 저녁, 가족 식사 + 거실 한쪽 워크스테이션 | 와이드 | happy | 배경 요소 |
| 4 | 밤, 잠든 집 + 로고만 은은히 발광 | 타이트 클로즈업 | calm | 클로즈업(핵심 검증) |

주의: Task 6.18(미해결)에 따르면 nonhuman 씬은 인물 묘사 지시가 빠져 mood의
표정/감정 채널이 죽고 조명 폴백만 남는다. 이번 시나리오는 전 씬에 사람이
등장하므로(장비는 배경/소품), `has_human_subject` 판정이 씬마다 어떻게
갈리는지(주 피사체는 nonhuman인데 인물이 프레임에 있는 케이스) 자체가 새로운
관찰 포인트 — 기존 6.18 조사 대상과 다른 케이스라 추가 기록 가치 있음.

## 스파이크 2단계 계획

### Phase 1 — 격리 프로브 (저비용 선검증)

`tests/probe_*.py` 패턴으로 `tools.generate_subject_ref_clip`을 씬 분할/승인
게이트 없이 직접 호출, 합성된 "로고+워크스테이션" 참조 이미지 1장으로 위 4씬
프롬프트 각각 클립 생성. 목적: 모델 자체가 로고를 깨뜨리지 않고 유지할 수
있는지부터 빠르게 확인 (파이프라인 배선 문제와 모델 한계를 분리하기 위함).

### Phase 2 — 경로 비교 (스크립트 vs 실제 UI)

같은 시나리오를 두 경로로 각각 1회 실행 후 비교:

- **(a) 스크립트/API 직호출** — `driver.py` 또는 curl로 `:8700` 직접 호출.
- **(b) 실제 LocalAI UI** — GatewayAgent 채팅에 로고+워크스테이션 합성 이미지
  첨부, 시나리오 입력, 승인 게이트(1-4 씬분할, 2-3 이미지, 3-5 클립) 다 밟아서
  진행.

**비교 지점**:
- `matched_image` / `subject_type` 판정값 (씬별로 (a)(b) 동일한가)
- 최종 씬 프롬프트(`style_bible` 반영 여부, 6.7 에코 버그류 재발 여부)
- seed (job_id 해시 유도 — (a)(b) 다른 job_id면 다른 seed가 정상, 참고용)
- 실제 ComfyUI에 전송된 그래프 JSON (해상도, reference_guidance_scale 등)
- 최종 클립 4개의 로고 육안 비교 — 텍스트/실루엣/색 뭉개짐, 씬 간 로고 형태
  드리프트 여부

## 성공 기준

- DaolFusion 메인 로고가 4개 씬 전부에서 원본과 동일한 실루엣·색(파란 원 +
  검은 트리·회로 라인)으로 식별 가능, 다른 로고로 변형되지 않음.
- NVIDIA 배지가 씬1/4(클로즈업)에서 최소한 "녹색 눈 모양 마크 + NVIDIA
  워드마크"로 알아볼 수 있는 수준 유지 — 완벽한 타이포그래피 재현까지는
  기대하지 않되, 다른 형태로 뭉개지거나 사라지지 않아야 함.
- (a) 스크립트 결과와 (b) UI 결과가 육안상 동일 — 다르면 그 지점(씬분할 판정 /
  프롬프트 조립 / 그래프 파라미터 / 렌더링) 중 어디서 갈라지는지 특정.

## 알려진 리스크 요인 (조사 항목)

1. 캡션 VLM(gemma4:latest)이 "로고가 새겨진 워크스테이션" 합성 이미지를
   정확히 nonhuman으로 캡션하는지 — 오판 시 human 경로(STANDIN/Face-ID)로
   잘못 라우팅되어 로고가 아예 무시될 수 있음.
2. `LTX_FACEID_WIDTH/HEIGHT`(1280×704) 리사이즈가 로고처럼 작고 세밀한
   텍스처를 얼굴보다 더 심하게 뭉갤 가능성 — 6.12는 얼굴 identity 붕괴
   사례였고 로고 판독성 문제는 별도로 실측 필요.
3. Task 6.18 미해결(mood-lighting 불일치)이 로고 씬 조명에도 영향을 주는지.
4. Flux Kontext I2I 로고 합성 단계 자체에서 로고가 왜곡될 가능성(6.19 스파이크에서
   Flux Kontext dev의 줌인/구도 드리프트가 이미 관측된 바 있음 — ControlNet 없이
   순수 텍스트 프롬프트로 합성하면 동일 문제 재발 우려, 필요시 6.19의 Canny
   ControlNet 픽스 재사용 검토).
5. NVIDIA 배지가 DaolFusion 로고보다 작게 들어가므로, subject_ref 경로의
   1280×704 리사이즈·이후 인코딩 과정에서 큰 로고보다 먼저·심하게 뭉개질
   가능성 — 배지가 통째로 사라지거나 읽을 수 없는 얼룩이 되는지가 리스크 2와
   별개로 확인할 지점(로고 2개의 크기 차이가 만드는 실패 모드).

## 후속 스파이크 — 씬별 재구성 참조 이미지 (Task 5 반영 예정, Phase 2b 완료 전 선행 기록)

Task 1~4 완료 후 사용자 관찰: "모든 영상에서 사물이 동일 위치에 고정, 배경 움직임
어색, 시나리오 스토리가 잘 안 담김, 구도 일정함." 원인 조사 결과 — subject_ref는
참조 이미지 **전체를 매 씬 첫 프레임 latent로 강하게 고정**하는 방식이라, 4씬이
같은 참조 이미지 1장을 재사용하는 한 구도가 수렴하는 것은 이 메커니즘의 구조적
특성이지 프롬프트 튜닝으로 풀 문제가 아님(`tools.py` subject_ref 독스트링:
"참조 이미지 전체를 첫 프레임 latent로 고정 — 실루엣·화풍 보존").

개선 방향으로 "씬마다 다른 구도의 참조 이미지를 Flux Kontext I2I로 미리 만들어
각 씬 전용 참조로 먹인다" 안을 씬1(책상 클로즈업)·씬3(거실 야간, 소형) 2개로
빠르게 스파이크(2026-08-12, `langgraph/tests/probe_logo_hw_recompose.py`,
`probe_logo_hw_recompose_i2v.py` — Plans.md/SDD 플랜에는 아직 정식 태스크로
편입 안 됨, 결과만 여기 선기록).

**ControlNet strength 0.15(구도 자유도 우선)**: I2I 재구성 자체는 구도가 뚜렷이
달라지고 로고/워드마크도 유지됐으나(`ref_scene1_dell.png`/`ref_scene3_dell.png`),
그 결과물을 다시 subject_ref I2V에 먹이자 **identity가 붕괴** — 씬1은 장비가
프레임 중간부터 완전히 다른 물체(모니터)로 바뀌었고, 씬3은 장비 위에 프롬프트에
없던 흰색 마스코트 캐릭터가 생겨나 점점 커짐(환각). "생성물(재구성 이미지)을 다시
생성 입력으로 먹이는" 체이닝 구조 자체가 원본 사진 재사용보다 더 불안정한 입력이
되는 것으로 추정.

**ControlNet strength 0.45(중간, 재시도)**: 씬1은 장비 identity가 3프레임 내내
안정적으로 유지되고(로고 포함) 손이 다가와 만지는 자연스러운 동작까지 나왔으나 —
**그 손이 해부학적으로 깨짐**(한 팔에서 손 2개가 따로 뻗어나온 것처럼 보임).
씬3는 장비 자체는 유지됐지만 여전히 환각(이번엔 허공에 뜬 발광 고리 오브젝트)이
있었고, **결정적으로 프롬프트가 요구한 "가족이 식탁에 둘러앉아 웃는" 내용이
전혀 렌더링되지 않음**(사람 자체가 아예 등장하지 않는 빈 거실).

**결론 — 이 모델(subject_ref/Wan i2v_14b)의 일관성 문제는 "사물이 약함"이
아니라 정반대다.** 참조 이미지에 있는 대상(장비)의 identity를 지키는 능력은
strength를 올릴수록 오히려 강해지고 안정적이다. 약한 지점은 **참조 이미지에
없는 새 요소를 그려 넣는 능력**(사람, 특히 다수 인물, 손 같은 정교한 해부
구조)이며, 이 능력은 장비 identity lock(strength)을 올릴수록 오히려 더
떨어지는 트레이드오프 관계를 보인다(strength 0.45에서 씬3의 가족이 통째로
사라진 것이 근거). 즉 "제품 하나만 나오는 히어로샷"류 콘텐츠에는 이 경로가
적합하지만, "제품 + 여러 사람이 함께 나오는 스토리"에는 구조적으로 약하다 —
사람 쪽도 identity를 안정시키려면 Face-ID/Stand-in 같은 별도 참조를 함께
줘야 하는데, 현재 툴셋엔 "제품 참조 + 사람 참조를 동시에 고정"하는 경로가 없다.

이 결론과 함께, 원본 사진(재구성 없이) 재사용 방식(Task 2/3에서 검증된 경로)이
"덜 예쁘지만 더 안전한" 기본값이라는 점도 Task 5 최종 비교에 함께 반영한다 —
재구성 경로는 구도 자유도를 얻는 대신 identity/스토리 안정성을 잃는 트레이드오프이며,
이번 2씬 스파이크로는 순이익이 나지 않았다(적어도 이 강도 범위에서는).

시도한 미검증 대안(다음 스파이크 후보): 참조 이미지를 diffusion으로 재생성하는
대신, ComfyUI의 기존 `RemoveBackground` 노드로 원본 실사 장비를 배경에서
잘라낸 뒤 그 실사 픽셀 그대로(재생성 없이) 새 배경 사진 위에 위치·크기만
Pillow로 바꿔 합성 — 장비 픽셀이 diffusion을 한 번도 안 거치므로 이번에 관찰된
"체이닝발 identity 붕괴"가 구조적으로 발생하지 않을 것으로 예상되나, 미착수.
