# 영상 분위기 통일 + 구도·자세 정의 + 씬 이미지 강제 지정

날짜: 2026-07-05 · 대상: `langgraph/` (approval agent)

## 문제

1. **분위기 불일치** — 씬별 프롬프트를 각각 독립된 LLM 호출로 생성해서, 전체 이야기의
   색감·조명·톤을 모르는 채 씬마다 룩이 따로 놀았다. 통일 장치는
   `STYLE_LOCK_TOKEN` 한 줄("anime style, ... vibrant colors")뿐. 시드(seed)도
   서버는 지원하지만 에이전트가 안 보내서 매 클립이 완전 랜덤.
2. **구도·자세 미정의** — 프롬프트 지시문이 "camera work and character actions"
   정도로 느슨해서 샷 크기/앵글/자세가 맥락과 무관하게 나왔다.
3. **씬 이미지 미반영(daorli 건)** — 참조 이미지는 업로드 시 `img_0.png`로
   개명되므로 원본 파일명("daorli") 매칭은 원리적으로 불가능. 자동 매칭(qwen
   캡션 기반) 단일 경로에만 의존했고, 놓치면 그 씬은 그냥 T2V로 갔다.
   승인 게이트(1-4)에 이미 "씬 2,4에 첫번째 사진 써줘" 수동 지정 기능이
   있으나(openwebui_anim_function.py `_try_assign_images`), 게이트에서 받은
   scenes에 검증 가드가 없었다.

## 해결 (변경 3건, 신규 기능 없음)

### 1. 스타일 바이블 (nodes.py, state.py)

- `node_generate_prompts` 시작 시 `state["style_bible"]`이 없으면 LLM 1회 호출:
  전체 시나리오 + 씬 목록 + 인물 캡션을 주고 **60단어 이내 영어 스타일 규격**
  (팔레트, 조명, 시간대, 무드, 카메라 톤, 화풍)을 뽑는다.
- 이 문자열을 state에 저장 → 재생성·재프롬프트 때도 같은 규격 재사용(안 흔들림).
- 모든 씬 프롬프트 끝에 기존 `STYLE_LOCK_TOKEN` 대신 바이블을 붙인다.
  LLM 실패 시 기존 토큰으로 폴백.
- **시드**: `job_id` 해시에서 결정적으로 유도, 한 job의 모든 씬에 동일 시드 전달.
  (state 필드 대신 해시 유도 — 재시작에도 동일, 배선 최소.)
  **재생성 씬은 시드를 빼고(랜덤) 보낸다** — 같은 시드+같은 프롬프트면
  똑같은 결과가 나와 재생성이 무의미해지기 때문.

### 2. 구도·자세 지시 (nodes.py)

- 씬 프롬프트 생성 지시문에 명시 요구: 샷 크기+카메라 앵글(씬 맥락에 맞게),
  인물의 구체적 자세·행동, 카메라 움직임.
- 씬 텍스트만 주던 입력에 mood + 스타일 바이블을 함께 줘 톤이 어긋나지 않게 한다.

### 3. 승인 게이트 이미지 지정 가드 (nodes.py)

- 게이트 1-4에서 사람이 수정해 돌려준 scenes에 대해:
  - `matched_image`가 실제 ref 파일 목록에 없으면 → None (T2V 강등)
  - `matched_image`는 있는데 `image_role`이 비었으면 → `"start"` (I2V)
- 이로써 기존 채팅 명령("씬 3에 두번째 사진 써줘")이 항상 안전하게 반영된다.
  자동 매칭이 놓쳐도 사람이 게이트에서 확실히 강제할 수 있다.

### 4. 시드 전달 (tools.py)

- `call_video(..., seed=None)` 파라미터 추가, 있으면 body에 포함.
  서버(:8500)는 이미 `seed`를 받아 `torch.Generator`에 넣는다 — 서버 무변경.

## 범위 밖 (하지 않음)

- 생성 속도(클립당 ~8분): 스텝/해상도/distill 모델 — 별도 작업으로 보류.
- 파일명 기반 자동 강제 지정: 업로드 시 개명되므로 불가능, 게이트 수동 지정으로 대체.
- 서버(hunyuan_server), openwebui function 코드: 무변경.

## 검증

- `python tools.py` — clean_llm_prompt 자체점검 유지.
- `driver.py --dry` — 그래프 전 경로(배선/interrupt/resume/ffmpeg) 통과.
- 실 job 1회 — 클립 간 색감·톤 육안 비교, `/state`로 style_bible·프롬프트 확인.
